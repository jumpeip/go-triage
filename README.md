# GoTriage — Go binary triage for Ghidra

GoTriage helps you spend your time on the **actor's code** in a Go binary instead of the
thousands of runtime, standard-library, dependency and compiler-generated functions around it.

It reads Go metadata **directly from the bytes**, so it works on unanalysed programs, stripped
binaries, and Go versions newer than Ghidra's built-in Go support. It has been tested on
go1.24, go1.25 (including `-trimpath`) and go1.27 PE binaries. The parsers also implement the
ELF/Mach-O, 32-bit and ARM64 paths, but those haven't been run against real samples yet.

## What it does

| Area | Details |
|---|---|
| **Symbol recovery** | pclntab layouts `0xfffffffb` (Go 1.2–1.15), `0xfffffffa` (1.16–1.17), `0xfffffff0` (1.18–1.19), `0xfffffff1` (1.20+): entry, size, name, source file, start line, funcID, flags. Locates the table by section name or by signature scan. |
| **Module metadata** | `\xff Go buildinf:` → Go version, main package/module, every dependency with version/sum/`replace`, build settings (`GOOS`, `GOARCH`, `CGO_ENABLED`, **`-ldflags` incl. `-X` variables**, `vcs.*`). |
| **moduledata** | Finds `runtime.firstmoduledata`, rebases function entries on `moduledata.text` (newer PE builds store `textStart = 0`), and calibrates the type-section base **empirically**, so it doesn't depend on a fixed field offset (go1.27 moved it). |
| **Types** | Decodes runtime type descriptors referenced by code (and typelinks when present): names, kinds, **struct field names/types** (handy for configs). |
| **Classification** | Every function → **Actor**, **Unknown** (likely actor), **Third-party**, **Stdlib**, **Runtime**, **Generated**, with a confidence score and the reasons. |
| **Compiler-generated code** | `<autogenerated>` wrappers, runtime *wrapper* funcID, `-fm` method values, `type:.eq.*` / `type:.hash.*`, linker markers, generic shape instances; closures (`.funcN`), `gowrap` (go statements), `deferwrap`, range-func bodies; package `init` is kept as owner code (it runs global initialisers). Runtime helpers are labelled `panic-path`, `stack-growth`, `write-barrier`, `mem-helper`, `lang-helper`. |
| **Capabilities & risk** | Callee rules (e.g. `os/exec.Command` → EXEC), library knowledge (e.g. `kbinani/screenshot` → SCREEN_CAPTURE), string rules (URLs, IPs, Run keys, injection API names, wallets, ransom notes…), indirect capabilities through actor call chains, and **pattern bonuses** (network+exec, enumerate+encrypt+rewrite, steal+exfiltrate, injection chain, loader…). Every point is explained. |
| **References** | A decoder-free byte scanner for x86 / x86-64 / ARM64 (calls, string literal + length, global string vars, func values, type refs), **merged** with Ghidra's own references when the program has been analysed (any processor). |
| **Ghidra markup** | Create missing functions from pclntab, merge Ghidra function fragments ("chunks") back into their owners, rename to Go names, namespaces (`GoTriage::Actor::github.com::x::y`), function tags (`GO_ACTOR`, `GO_STDLIB`, `GO_CAP_EXEC`, `GO_SUSPICIOUS`), bookmarks (actor functions + indicator strings), background colours by risk, plate comments with the explanation, Go string literals defined. User-defined names and comments are never overwritten. **Clear Markup** removes bookmarks, tags, comments and colours. |
| **Build artefacts** | GOROOT, `-trimpath`, actor source tree, user names leaked by paths (source tree / GOPATH / GOROOT), CI-runner detection, garble obfuscation heuristic. |
| **Exports** | JSON (full), CSV (functions), Markdown (summary), **draft YARA rule** (actor function names from pclntab + indicator strings + module/build paths), Graphviz DOT of the actor call graph. |

## The GUI (Window → Go Triage)

* **View** selector: *Likely actor code* (default), *Actor + third-party*, *Everything except
  runtime/generated*, *Everything*, or tick individual categories. Optional
  *+ generated code of actor packages*, minimum confidence / risk, a capability selector, and
  a filter box that takes `pkg:`, `cap:`, `tag:` and `re:` prefixes.
* **Overview**: version, module, build settings, how much of the code each category takes up,
  actor entry points, highest-risk actor functions, notable libraries, indicator strings, the
  actor's source tree. Click a link to jump there.
* **Functions**: address, category, actor, confidence, risk, package, function, capabilities,
  *why*, source file:line, size, callers, callees, noise calls, tags. The detail pane below gives
  the full explanation: meaningful calls (runtime/compiler noise hidden), callers, strings and
  types used. Right-click to **mark as actor / not actor** (saved in the program), filter to the
  package, or copy the explanation.
* **Packages**: one row per package with its category, why it was attributed that way, its
  module@version, capabilities and max risk. Double-click a package to filter Functions to it.
* **Strings**: literals referenced by the functions that pass the current filter, with indicator
  tags. *Indicators only* shows just the tagged ones.
* **Types**: recovered type descriptors, with struct fields, filtered to types the actor uses.
* **Xrefs**: callers and callees of the selected function (follows the listing cursor). Can hide
  runtime and compiler noise.
* **Call Graph**: lazy call tree rooted at the selected function, the actor entry points, or the
  actor roots (functions no other actor code calls). In *Actor focus* mode runtime and generated
  callees are hidden and library calls are folded into a *library / API calls* node. Can export
  to DOT.
* **Build / Modules**: build settings, and each dependency with its knowledge-base class
  (library / dual-use / offensive) and how many of its functions are in the binary.
* **YARA**: draft rule you can regenerate, copy or save.
* Toolbar: **Analyze** (re-runs and reloads the knowledge base), **Apply Markup** (opens an
  options dialog), **Clear Markup**, **Export**, **Knowledge base**, **Help**.

Menus: *Window → Go Triage*, *Analysis → Go Triage → Analyze Go Binary / Apply Markup (defaults)*.

## Install

1. Build: `build.bat`, or
   `gradle -PGHIDRA_INSTALL_DIR=D:\ghidra_12.2_PUBLIC buildExtension`.
   This produces `dist\ghidra_12.2_PUBLIC_<date>_GoTriage.zip` and `dist\go-triage-cli.jar`.
2. In Ghidra: *File → Install Extensions → +* and pick the zip, then restart Ghidra.
   (Or unzip it into `%APPDATA%\ghidra\ghidra_12.2_PUBLIC\Extensions\`.)
3. In the CodeBrowser: *File → Configure → Miscellaneous* → enable **GoTriagePlugin** (Ghidra
   usually offers this itself after a restart, when it finds new plugins).

## Headless / batch

```
analyzeHeadless <projDir> <projName> -import sample.exe ^
    -postScript GoTriageHeadless.java <outDir> [apply] [actor-only]
```

This writes `<name>.gotriage.{json,csv,md,yar}` to `<outDir>`. With `apply` it also writes the
markup into the program (no colours in headless mode).

## Standalone CLI (no Ghidra)

```
java -jar dist\go-triage-cli.jar [--json f] [--csv f] [--md f] [--yara f] [--actor-only] [--kb dir] sample.exe
```

`tools\go-triage.bat` wraps this. It is useful in sandboxes and pipelines, and gives the same
classification as the plugin (the CLI uses the byte scanner only).

## Knowledge base (editable)

The `data\` folder holds tab-separated files, and each one documents its format in its header:

| File | Purpose |
|---|---|
| `stdlib_packages.txt` | top-level std path elements; which packages count as *runtime* |
| `known_libraries.tsv` | module prefix → `library` / `dual-use` / `offensive`, capabilities, description |
| `capability_rules.tsv` | callee name/package rules → capability |
| `string_rules.tsv` | regex → tag, capability, weight |
| `capabilities.tsv` | capability → risk weight and description |

Each file is loaded from the first of these places that has it:
`%APPDATA%\ghidra\<ver>\GoTriage\` (your overrides), then the installed extension's `data\`,
then the copy bundled in the jar. Press **Analyze** to reload after editing.

## How attribution works (in order of strength)

1. **Build info**: packages in the main module → Actor (92). Dependency modules → Third-party.
   A dependency `replace`d by a local directory → Unknown/likely actor (65). If build info is
   present, any non-std package that no dependency provides → Actor (80).
2. **pclntab source paths**: files under GOROOT → Stdlib; `/pkg/mod/` or `@vX.Y` → Third-party;
   an absolute path outside both → the author's local tree → Actor (85). A `-trimpath` path
   with no module version → Actor (70).
3. **Knowledge base**: known library prefixes → Third-party.
4. Otherwise → Unknown (55), or Unknown (50) for garble-style random package names.

`package main` is always Actor (95). Compiler-generated functions keep their owning package's
category in `ownerCategory`, so *+ generated code of actor packages* can bring them back.

## Limitations

* Packed binaries (e.g. UPX) have to be unpacked first. An encrypted or removed pclntab (some
  obfuscators) can't be parsed.
* garble randomises package and function names. GoTriage flags this and still separates the
  runtime, but attribution of obfuscated packages falls back to *Unknown*.
* Risk is a triage heuristic for ordering, not a verdict: legitimate tools score high on
  capabilities too.
* Without Ghidra analysis, the byte scanner covers x86, x86-64 and ARM64. For other
  architectures, run auto-analysis first so Ghidra's references can be used.

## Testing

* `tools\harness\...\GuiHarness.java` renders the real `TriagePanel` offscreen with real
  analysis results. It drives the view modes, filters, selection, Xrefs and Call Graph, and
  writes one PNG per tab. It's not shipped in the extension. Build the extension first, then
  compile it against `build\classes` plus the Ghidra Framework/Base jars.
* Headless integration: run `GoTriageHeadless.java` with `apply`, then inspect the program
  (namespaces, tags, bookmarks, plate comments).

## Layout

```
src/main/java/gotriage/core    parsers, classifier, scoring, reports, YARA (no Ghidra dependency)
src/main/java/gotriage/cli     standalone CLI + raw PE/ELF/Mach-O mapper
src/main/java/gotriage/ghidra  plugin, GUI provider, markup, Ghidra reference collector
ghidra_scripts/                GoTriageHeadless.java
data/                          knowledge base
tools/                         CLI launcher, offscreen GUI test harness
```
